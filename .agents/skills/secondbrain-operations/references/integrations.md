# Integrations and configuration

| Variable or platform setting                                                                 | Code consumer                                                                      | Exposure                                                                                                                                                                    |
| -------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`                                  | `src/lib/supabase.ts` browser client                                               | Public by design; RLS remains mandatory.                                                                                                                                    |
| `SUPABASE_SERVICE_ROLE_KEY`                                                                  | `getDatabaseClient()` and protected server routes                                  | Server secret; bypasses RLS.                                                                                                                                                |
| `OPENAI_API_KEY`                                                                             | AI chat, person extraction, transcription, stylization, summaries and quote routes | Server secret. Verify authorization, limits, and usage cost.                                                                                                                |
| `RESEND_API_KEY`                                                                             | Feedback API; SMTP credential for Supabase Auth when configured                    | Server secret. Sender domain must be verified.                                                                                                                              |
| `NEXT_PUBLIC_STRIPE_PUBLISHABLE_KEY`                                                         | `CheckoutForm.tsx`                                                                 | Public key; match test/live mode to server key.                                                                                                                             |
| `STRIPE_SECRET_KEY`, `STRIPE_PRO_PRICE_ID`, `STRIPE_ELITE_PRICE_ID`, `STRIPE_WEBHOOK_SECRET` | Stripe route handlers and plan endpoints                                           | Server secret except price IDs; mode, products, and webhook endpoint must match.                                                                                            |
| `STRIPE_CHECKOUT_ENABLED`                                                                    | Plan endpoint and checkout route                                                   | Set to `true` only when accepting payments; defaults to disabled. Checkout also requires every Stripe variable above. Paid plans remain visible while checkout is disabled. |
| `BILLING_EMAILS_ENABLED`                                                                     | Billing email queue worker                                                         | Defaults off. Enable only after reviewing sender, templates and worker scheduling; requires Resend and cron credentials.                                                    |
| `CRON_SECRET`                                                                                | Subscription expiration endpoint                                                   | Server secret if a scheduled request calls that route. The route rejects requests when absent.                                                                              |

Auth provider settings live in the Supabase dashboard: Google OAuth client credentials, authorized redirect `https://<project-ref>.supabase.co/auth/v1/callback`, site URL/redirect allowlist, and custom SMTP. Do not paste a Google client secret into `NEXT_PUBLIC_*`. Password recovery uses the app's current origin as `redirectTo`; make sure the deployed origin is allowlisted and reachable.

The app workspace is `secondbrain/` (Next 16); the marketing workspace is `secondbrain-landing/` (Next 15). The app's Vercel project is `secondbrain-app`, its Root Directory is `secondbrain`, and its production hostname is `app.secondbrainapp.com`. The landing uses `secondbrainapp.com`. Confirm the correct project before changing env vars or deploying. Domain DNS is managed separately from Vercel project assignment and TLS. For a release, check `npm run build` in both workspaces; each build checks for numbered conflict copies before Next compilation. Check preview HTTP and authenticated behavior, live environment configuration, Auth redirect, mail delivery, and any payment/webhook flow being enabled. A successful build alone does not confirm the domain, external Auth, mail, or Stripe services.

For a Vercel Domain Error, inspect the build result and alias assignment separately: a deployment can be `READY` while `aliasError` records a failed domain assignment. Verify the domain is attached to the intended project's Production environment, points to the intended commit, and serves HTTPS with a valid certificate. Resolve stale or conflicting domain associations before retrying the same source deployment; do not change application code to repair an alias collision.

Keep existing payment maintenance routes available even when new checkout is disabled. A cancellation tied to a real Stripe subscription must succeed at Stripe before the app records it as scheduled; return an error instead of inventing a renewal date if Stripe fails.

## Automated verification

The root commands and coverage matrix are in [docs/TESTING.md](../../../../docs/TESTING.md). `npm run test:all` runs Vitest coverage, disposable PostgreSQL security tests, both isolated production builds and desktop/mobile Playwright flows. CI runs these gates without production credentials. Do not deploy from `.next-test`; normal builds use `.next`. The test build flag is `SECOND_BRAIN_TEST_BUILD=1` and must not be set in Vercel.

## OpenAI model contract

The canonical identifiers are in `secondbrain/src/lib/ai-models.ts`: all text features use `gpt-6-luna`, and speech-to-text uses `gpt-transcribe`. Both use the existing server-only `OPENAI_API_KEY`. The app pins the OpenAI Node SDK to `7.25.0` for typed support of the current request fields.

Stylization, person extraction, emotional analysis, summaries and quotes use Responses with `reasoning.effort: low` and `text.verbosity: low`. Personal and person chats keep Chat Completions without tools, existing history and sampling settings, with `reasoning_effort: none` and `max_completion_tokens` limits. Do not restore `minimal` or the legacy `max_tokens` parameter. If enabling reasoning in chat, remove sampling fields such as `temperature` as required by the API.

Transcription uses `/audio/transcriptions`, `languages: ['es']` as a language hint, and the JSON response's `text`. Preserve actual recording MIME and bytes; set an extension matching the MIME rather than labelling every upload MP3. Keep the 25 MB provider file ceiling and reject empty transcripts. Existing app return fields stay `text` and `audioUrl`; the provider's detected languages do not change this contract.

Official references: [GPT-6 Luna](https://developers.openai.com/api/docs/models/gpt-6-luna), [GPT-6 parameter compatibility](https://developers.openai.com/api/docs/guides/latest-model#update-api-and-model-parameters), [file transcription](https://developers.openai.com/api/docs/guides/speech-to-text). Model access and billing still depend on the OpenAI project behind the deployed key; mocked tests do not establish that access.

## Billing and email contract

Read [docs/SUBSCRIPTIONS.md](../../../../docs/SUBSCRIPTIONS.md) for the normalized schema, UTC quotas, provider/worker flow and release dependencies. Apply the versioned database schema before a release that consumes new tables/RPCs; verify live rows and privileges. Never mix old JSON counter writers with the reservation service. Retain existing provider references and historical usage.

Stripe Node 18.4 uses its typed API `2025-07-30.basil`: subscription dates are on items, invoice relationships under `parent.subscription_details`. Webhooks re-read provider state, and commit their unique event, subscription state and mail queue together. Return-page verification reads only. Checkout/customer creation have stable idempotency keys; an existing subscription goes to Customer Portal. Configure/test the portal's products, allowed changes, proration and locale before enabling billing. Both checkout and portal remain disabled by the explicit checkout flag. New checkout validates provider price currency, unit amount and monthly interval against the advertised euro plans.

Transactional email layout and escaped content live in `src/lib/email-templates.ts`. Regenerate portable Supabase Auth templates, subjects and synthetic previews with `node scripts/build-email-previews.mjs`. Version the templates; applying them to hosted Auth is a separate release action. Use official ConfirmationURL/Token placeholders, Spanish copy and accessible single-column tables. Do not enable security notifications without preparing their corresponding templates.

Feedback uses authenticated sender email, server rate limiting and Resend idempotency. Billing mail is queued with provider events; its worker is gated by `BILLING_EMAILS_ENABLED` and `CRON_SECRET`, selects confirmed Auth recipients and claims jobs with `SKIP LOCKED`. Lease is ten minutes, retries stop after five attempts or 23 hours (before provider idempotency expires). Monitor failed jobs when scheduling the worker. Tests use fake recipients and never send real messages.

Checkout keeps one request UUID per mounted user/plan attempt, including retries after network errors. Do not generate a fresh idempotency key on each retry; changing the user or plan starts a new attempt. Avoid logging billing contact details in the browser.
