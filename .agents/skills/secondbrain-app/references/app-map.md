# Private app map

## Screens

- `src/app/page.tsx`: signed-in diary workspace; coordinates `Sidebar`, personal chat, settings, statistics, people panel, audio, and the current entry. Auth UI appears when there is no session.
- `src/app/login`, `signup`, `reset-password`: Supabase Auth entry points. `src/components/Auth.tsx` owns the combined sign-in/sign-up behavior; `/signup` passes signup mode even without a plan query.
- `src/app/subscription`: plan selection and checkout UI; `src/app/billing/return`: Stripe checkout return and verification. `src/app/dashboard` is the private operational administrator screen, reached only by entering its URL; do not add a menu link. `src/app/admin` remains a legacy owner-scoped diagnostic screen that rejects manual paid-plan assignment.
- `src/app/layout.tsx`: Spanish document metadata, viewport, `AuthWrapper`, welcome manager, and chunk error handling.

## Components and state

- `src/contexts/SupabaseAuthContext.tsx` and `src/hooks/useAuth.ts`: session, app user, profile, provider, and sign-out. Profile load/create runs after a session arrives.
- `src/lib/store.ts`: Zustand current date, current diary entry, editing, and transcriptions. `Sidebar.tsx` changes date and marks dates that have entries; the page fetches the selected entry.
- `src/components/DiaryEditor.tsx`: reusable editor presentation; the main page also contains integrated editing and save handlers. Trace which path a screen actually renders before editing.
- `PeopleManager.tsx`: people list, details and editing, search, and `PersonChat`. Keyboard-accessible accordion headers show initials, name and current relationship/role. Compact actions use a fixed “Abrir chat” label with the full person name in the accessible label; long names must not expand or collide with Edit. Facts are grouped by category in dated timelines with dates below the text. Preserve full history, normalization and original dates while adjusting presentation.
- `PersonalChat.tsx` and `PersonalChatButton.tsx`: chat about the user's diary. `PersonChat.tsx`: chat scoped to a person.
- `AudioRecorder.tsx`, `TranscriptionsList.tsx`: browser recording, transcription request, and entry association. Recording requires a current entry.
- `StatisticsWrapper.tsx` dynamically loads `Statistics.tsx` without SSR. The controller fetches `/api/statistics/analytics` only for an authorized paid plan; opening the screen never generates an AI report. `statistics/StatisticsDashboard.tsx` renders a full-width emotion timeline, a daily dominant-emotion calendar and selectable person bubbles. `PeopleBubbles.tsx` uses bounded deterministic circle packing, proportional typography and reduced-motion support. Date/person callbacks open the diary or canonical person panel. No personal statistics are cached in localStorage. The emotion timeline uses 100% stacked columns ordered top-to-bottom as happiness, tranquility, neutral, stress and sadness (`timelineEmotions` in `presentation.ts`; reverse that order when rendering Recharts stack children). Overview controls and tooltip rows follow the same visual order. Columns follow chronological entry order, omitting days without analysis so long inactive spans do not compress the actual entries. Date labels and tooltips always refer to the original diary dates. Sparse histories and the latest 30 days retain daily scores; older dense histories stay bounded below 180 points. Older dense histories use bounded buckets whose tooltip and accessible table name the actual first/last sampled dates and sample count; never label a period mean as an empty diary date. The API retains null gap markers and real zero; the column chart renders only analysed samples. `mood-distribution.ts` computes presentation-only shares by score / sum × 100, using largest-remainder rounding to one decimal so displayed totals are exactly 100%. Missing dimensions remain unknown; a zero total has no distribution and must not become Neutral 100%. Top cards show normalized per-dimension period averages. Emotion selection highlights its band while keeping all five bands and the denominator unchanged. `EmotionTooltip.tsx` shows relative percentages, original intensities and partial-analysis/zero-total notes; the accessible table retains the original scores. The paid controller reads fresh data on opening, period/manual refresh and returning to a visible tab (coalescing focus/visibility); a local clock check reloads only when Madrid's diary day changes, without minute-by-minute API polling or AI generation. Unmount/account changes abort obsolete replies.
- `statistics/PersonEmotions.tsx` renders five interactive emotion gauges inside the selected bubble's side card, replacing the recent-mention date list and separate emotion section. Missing scores remain unknown; real zero remains zero. These are means in entries mentioning the person, never a claim that the person caused them. `presentation.ts` shares the five-emotion palette (Neutral is gray) and Spanish UTC date labels. Keep five controls usable on narrow screens; omit missing score chips and disable ranking controls without samples.
- `statistics/PersonEmotionDialog.tsx` uses a native modal dialog (focus containment, Escape, focus restoration and mobile scrolling) to fetch rankings only on explicit emotion selection. GET `/api/statistics/person-emotions` ranks the full selected period, not only recent dates, by descending score then descending date. Show all saved emotion chips, open the actual diary date and load additional pages explicitly. Changing emotion or closing ignores obsolete replies; failures allow retry without removing prior loaded entries. Native selected tabs must not reset their own results.
- The person map has ordinary bubble groups of 12 and a focused connections view with the selected person in the centre plus 11 paged neighbours. All registered co-occurrences remain reachable across groups; do not add a separate name list or a physics loop. `PeopleBubbles.tsx` clips SVG lines outside circles and provides touch hit areas, Enter/Space and accessible pair/count labels. Stable hit areas must not move with decorative animation.
- `statistics/ConnectionDetails.tsx` fetches excerpts only when a paid user selects a line, through authenticated GET `/api/statistics/connections`. It shows dates, saved emotions and bounded text excerpts; entry callbacks open the actual diary date. Close, period/pair/identity/entitlement changes discard old responses. Errors stay inline with retry. Connection counts mean shared mentions in an entry, not meetings or a relationship between the people. Free preview uses static examples and performs no requests.
- `Settings.tsx` suggestion/bug forms persist through authenticated `POST /api/send-feedback`, retain drafts on failure and show the safe server error. Empty messages are disabled and input is limited to 5,000 characters. The verified account email is read-only. `/?settings=true` opens this view on authenticated arrival from subscription management. Saved feedback remains successful even if email notification fails. On small screens, keep one column, compact nested padding, and non-shrinking section icons; floating chat/people shortcuts are hidden in Settings so they do not cover form controls. `SettingsDialog.tsx` portals subscription confirmations to the document body as native dialogs, avoiding fixed positioning inside backdrop-filter containers. Preserve focus restoration, Escape, body scroll locking, and a scrollable 90dvh maximum height.
- `dashboard/AdminDashboard.tsx` gates rendering on the server overview response. It owns overview/user directory/feedback tabs; `useDashboardResource` aborts stale requests and hides previous filter/account data. User and report details use native modal dialogs with focus containment, Escape and mobile scrolling. Triage uses optimistic versions. Dialog height must use a flexible body with `min-height: 0`, never subtract a fixed header height: long account names change header height. On touch screens use at least 44px controls and 16px editable fields to avoid iOS focus zoom; narrow filters wrap, and plan/usage tables scroll inside their own card. At 380px and below, overview metrics use one column and tab icons sit above labels. Counts/plan limits come from SQL, not browser-side loading of every user or diary. See [administration](../../../../docs/ADMINISTRATION.md) for the contract.
- `UserHeader.tsx`, `WelcomeManager.tsx`/`WelcomeModal.tsx`: account settings, navigation, and first-use state.
- `src/hooks/useSubscription.ts` and `src/middleware/subscription.ts`: effective plan, feature limits, and monthly usage; `src/lib/subscription-state.ts` shares one server snapshot across consumers and ignores obsolete identity requests. Keep displayed plan behavior consistent with these modules and the server routes.

## UI conventions

- UI copy is primarily Spanish. Preserve keyboard, focus, and touch behavior, especially the mobile sidebar, people panel, calendar, and modal flows.
- Styles use Tailwind utility classes plus `src/app/globals.css` and CSS modules for PeopleManager, PersonalChat, Statistics, and WelcomeModal. Reuse the established palette and responsive breakpoints rather than adding a parallel design system.
- Assets live under `public/`; `next.config.ts` permits Google profile images and sets CSP/security headers. Review CSP when adding an external API, frame, font, or image host.
- The transparent square logo source is root `assets/logo_lumadiary.png`. `node scripts/build-brand-assets.mjs` publishes `/brand/logo.png`, sized PNG icons and favicons in both workspaces; legacy logo URLs serve the same artwork for cached pages. Keep square display dimensions, with separate text for horizontal brand presentation.

## State and regression checks

AI requests run on the server; model identifiers and reasoning baselines are centralized in `src/lib/ai-models.ts`. Both audio recorder paths retain `MediaRecorder.mimeType` (or the emitted chunk's type) when creating the Blob. The transcription route assigns a matching filename without converting the recording bytes. See the operations integration reference for model/API compatibility.

Both recording paths use `src/lib/transcription-client.ts` for authenticated uploads, matching filenames and validated responses. The integrated diary attempts each new recording once automatically. Failed audio remains in memory with playback, download, explicit retry and discard; never clear it in a failure `finally` or create an automatic retry loop. Revoke preview URLs after disposal/unmount. A recording belongs to its owner and diary date; ignore late replies after either changes, and append successful text to the latest draft. Provider credit exhaustion is a service availability failure, not a subscription quota; show the safe API message inline without triggering a Next development error overlay.

Personal and person chats derive quota loading from `useSubscription.loading`: disable sending and show a loading status until it resolves. A missing usage result is a load failure, not an exhausted quota; keep those messages distinct. The API still checks real limits independently of these UI controls.

`useDiaryStore` invalidates pending loads/saves when the selected date or request changes. Clear prior entries and audio on date changes. Only reuse an entry ID when both its owner and date match the current save. Keep the store error visible in the integrated diary and preserve drafts after failed persistence. `useSubscription` clears plan/usage on logout and ignores obsolete requests. The Auth provider also ignores profile responses from an earlier session after logout, account changes or unmount. Google-linked identities use the providers array consistently. Audio preview object URLs and microphone tracks must be released, and duration limits must use current recorder state rather than an old React closure. Follow [the test matrix](../../../../docs/TESTING.md) when changing these flows.

Subscription state refreshes after successful/quota-limited cost-bearing requests, across tab notifications, on focus and every visible minute. Display the UTC reset time and loading/error states; a load failure never means zero consumption. Derive subscription details from the shared snapshot when rendering settings. Feedback reply email is the authenticated account email. Cancellation refreshes shared state without reloading the page.

Statistics default to all diary history, with rolling 7/30/90/365-day filters applied to every graph. Preserve historical dates and real missing emotional values; never substitute zero, infer meetings from mentions, or imply causation/diagnosis. `diary-analytics.ts` derives metrics on the server, groups long mood timelines into bounded buckets and counts normalized names once per entry. No KPI cards, weekday rhythm card or person-name ranking list are shown. People are accessed through searchable bubbles; use paged groups of 12 so every name remains reachable. The calendar shows a labelled 12-week Monday–Sunday window; all-history mode ends in the week of the last recorded entry. Colour each day using its own highest valid emotion score, preserve ties with combined colours, and distinguish missing analysis from missing entries. Do not use timeline bucket averages to colour daily cells. Abort obsolete graph requests and discard report replies after identity/entitlement changes.

Free users see `StatisticsPreview` with literal synthetic `preview-data.ts`, blur, `aria-hidden` and `inert`, plus the real `/subscription` upgrade link. Do not fetch, aggregate or generate their private statistics. Subscription loading/error is not free-plan denial. Report quota exhaustion never blocks paid graphs. Only the explicit generate/regenerate action rebuilds the weekly report and citation, consuming one reserved report; display remaining quota and cached generation time. Preserve image sharing/downloading in `statistics/share-quote.ts`.

Checkout remains visible but disabled when unavailable. Enabled hosted checkout redirects to the server-returned HTTPS Stripe URL, validated by `billing-navigation.ts`, without loading a browser Stripe SDK. `BillingPortalButton.tsx` opens explicit billing management and ignores replies from a previous account. Plan cards support keyboard selection. Existing subscriptions, including incomplete provider payments, use the customer portal; checkout-return UI distinguishes payment confirmation from plan synchronization.

Account deletion closes open checkout sessions and deletes the verified Stripe customer before removing the Auth identity, so subscriptions cannot renew after profile/owner data disappears. This ends paid access immediately and differs from period-end cancellation; preserve this disclosure in the explicit Settings confirmation. A provider failure must retain the account for a safe retry. No refunds are implied by account deletion.

Checkout ignores obsolete replies on account/plan changes. Pending checkout for another plan exposes an explicit cancel-attempt button, which expires the unpaid provider session before enabling a fresh attempt. The server shares the original attempt across tabs; a completed payment must be reconciled rather than canceled as an unpaid checkout.

Person display and editing use `person-information.ts` normalization. Single profile inputs show the latest chronological value; changing them appends a dated change without deleting prior history. Multi-line editing preserves a separate original date for every repeated event, including notes without a recorded date. Empty inputs/textareas must remain editable and removable. Match initial person selection by normalized name or ID, clear conflicting search/collapse state and scroll the selected header into view after the people load, and ignore obsolete load/save replies after account changes.

Diary analysis replaces `mentioned_people` with the complete returned membership, including an empty list when no people remain. Refresh the people panel after both extraction and diary persistence, because mention counts derive from saved diary dates. Show API errors, persistence failures and partial emotional-analysis warnings. Never auto-save analyzed text after the account/date or draft changed while waiting, and prevent duplicate in-flight analyses. Do not log diary text, personal facts, model responses or credentials.

Emotion analysis uses `src/lib/mood-analysis.ts` for the prompt, strict five-key nullable schema and parser, with `diary-analytics.ts` defining `MOOD_KEYS`. Happiness, tranquility, stress, sadness and neutral are independent 0–100 intensities; do not normalize stored/model scores to a sum of 100 or balance happiness against sadness. The overview chart alone presents their normalized relative distribution. Neutral describes an emotionally ordinary experience, not how descriptive the prose is or how many emotional adjectives it contains. The prompt must consider contextual enjoyment/satisfaction and urgency/pressure, allow happiness and stress to coexist, respect the writer’s self-report and distinguish phases of the day. Humor or eventual success does not cancel pressure; neutral is not a filler for absent emotion words. Unknown dimensions stay null; calm requires evidence of tranquility/wellbeing. Evaluate the author rather than attributing another person's emotions to them. Analyze the whole validated entry (up to 50,000 characters), not a truncated opening. Do not automatically reanalyze history: old Neutral values stay unknown until an explicit diary analysis. Central keys must propagate to overview, calendar, person averages, entry chips and rankings.

`dashboard/DiaryReanalysisDialog.tsx` exposes explicit per-user reanalysis from the directory, with server counts, provider cost disclosure, persisted progress, pause/resume/cancel and failed-only retry. GET never invokes AI. Initiate from a user action, keep the request UUID after a lost start response, and use an in-flight ref to reject duplicate clicks. Process one entry per awaited POST, stop on a failure or busy lease, and stop subsequent calls when closing/unmounting or losing admin access. A current server request can finish after pause; do not present pause as immediate cancellation. No job text or model result appears in the browser. Keep native dialog scrolling, focus restoration and mobile controls; never automatically start a new run when reopening.
